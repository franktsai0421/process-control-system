## 一、這次修正的邊界

- 在現有「資料後台 → 品質系統 → IQC」上修改，不另外新增第二個頁面；保留已匯入的 187 個零件、538 個原始錯誤代碼及 538 個原始檢查項目。不可藉由重新匯入覆蓋使用者在 local 草稿已修改的值。
- 頁面在瀏覽／生效版本是唯讀；點「開始修改」後進入草稿，才顯示新增、編輯、刪除與儲存。上方沿用版本選擇、儲存草稿、送出主管審核、版本確認平台；送審使用最後成功手動儲存的snapshot，送審後鎖定，核准才生效；顯示修改、確認的 USER 與時間。
- 後續日常頁面已移除Excel匯入；保留來源稽核與待確認資訊且預設收合，不擠掉編輯空間。不要把「7 個問題」理解成 7 筆資料必然錯誤，須保留原始報告及可查看細節。

## 二、主畫面依 `01_iqc_main.png`

1. 左欄寬度足以讓「零件編號＋名稱／供應商／類別」分行閱讀；列表有內部捲動，最上方放搜尋、供應商篩選及類別篩選。搜尋框輸入編號或越文名稱，可與兩個篩選同時作用，顯示「符合／總數」。清單點某列，右側切換到該零件；保留選取狀態。
2. 「修改供應商清單」與「供應商」標題同一行、右側對齊；「修改類別清單」與「零件類別」標題同一行、右側對齊。管理大量資料時依 `04_compact_registry.png` 使用可搜尋的精簡列：名稱、編輯、刪除；頂端先列 `NƯỚC NGOÀI`、`CÔNG TY`，新增欄與按鈕放清單底部。仍有零件引用的供應商或類別不能直接刪除，應顯示需先改派的數量。不要把每家供應商／每個類別做成佔滿整個螢幕的輸入卡片。清單中的資料值一律越文原文。
3. 每個零件清單列：左側只有**第一張**照片縮圖（或無圖佔位）；縮圖**下方**小型「修改／刪除」按鈕；右側分行呈現編號＋越文名稱、簡短規格、實際供應商、越文類別。點縮圖開啟可左右切換的全部照片大圖；點列空白處選取零件，不應誤觸刪除。
4. 右上零件摘要列名稱、**規格**、唯一類別、依序排列的第一／第二／後續供應商及多張照片縮圖；沒有需要讓同一個供應商以「原始供應商文字」重複出現兩次。原字串有疑義時，放可收合的匯入備註，不佔主要欄位。
5. 右下按錯誤代碼分組，組內檢查項目一列一項；閉合列顯示編號、越文項目摘要、規則摘要、啟用狀態，點擊展開完整已存內容及編輯入口。展開第 2 項或切換零件後回來，已存的第 1、2 項仍能看見；使用者正在編輯的草稿不得因收合而丟失。每個錯誤代碼區塊的操作不擠在標題旁；新增項目可放該組底部。小螢幕改成上下排列，但保留相同操作順序。

## 三、彈窗依 `02_part_editor.png`、`03_inspection_rules.png`

- 零件新增／編輯：編號、越文名稱、越文規格、**單一**類別；供應商依序新增第一、第二、第三……行，各行選擇既有供應商，可更換、移除、不得重複選同一家；多張照片可新增、排序、移除。清單第一張隨照片順序更新。未選供應商的異常零件可以保存草稿，異常須顯示待確認。
- 錯誤代碼：保留 Excel 原代碼，新增代碼按原編碼接續、不重編不重用。新增／修改名稱直接存草稿；刪除需雙重確認。
- 檢查項目：保留原編號及 Excel 內容，可收折。編輯時直接變更欄位，**不放逐條「修改」按鈕**；每項至少保留一條檢查規則。`按批次／依樣品` 選 AQL、固定件數、批次數量、自訂，每一種都要填相應數值；自訂還要填越文項目名稱。`按時間` 選週、月、季、半年、年、自訂，不填數量；時間自訂只填越文名稱。依類型切換只顯示適用欄位，隱藏欄位不能干擾驗證。
- 所有刪除（零件、供應商、類別、照片、錯誤代碼、檢查項目、規則）均需兩次明確確認；不能只靠紅色按鈕或一次瀏覽器 `confirm`。若刪掉最後一條規則，必須阻止並說明至少保留一條。

## 四、已觀察到的差異與應修正處

| 目前畫面／行為 | 定案處理方式 |
|---|---|
| 供應商及類別管理彈窗是一家一個巨大輸入卡片，刪除鈕又黑又顯眼。 | 改為搜尋＋精簡列＋低權重編輯／刪除；`NƯỚC NGOÀI`、`CÔNG TY` 排第一。 |
| 清單列的「修改」「刪除」是大片獨立按鈕，和文字一起塞進窄欄。 | 縮圖下方放小型次要按鈕，列本身只負責選取。 |
| 零件摘要另顯示「原始供應商文字」且與供應商重複。 | 正常零件只列排序後的供應商；歧義來源留在匯入備註。 |
| 零件與錯誤代碼詳細資訊佔太多高度，每組一張大卡且操作擁擠。 | 保留錯誤代碼群組，項目改為精簡可收合列；展開內容可見編輯過的規則。 |
| 搜尋框輸入一次 `3` 出現 `33`。 | 修正重複 input/keydown/IME 處理或重複 bind；保持輸入框焦點與游標位置。驗收：依次輸入 `3`、退格、`3010202`、越文重音字，各按一次只增加一字；切換篩選不複製字或清掉輸入。 |
| 顯示「Phao điện」卻沒有清楚的欄位名稱。 | 標為「規格 / Quy cách」；不要誤當零件類別。 |
| 新增／修改檢查項目的規則編輯一列橫排，長文字和多條規則難讀。 | 改為每條可收合的規則卡，批次與時間的欄位依選項呈現，未輸入的必要欄位清楚標示。 |

## 五、已決定的資料關係與仍需查證的實作事實

- `NƯỚC NGOÀI`、`CÔNG TY` **目前按使用者決定是供應商名稱**，不要從名稱推導第二套強制「供應商來源」欄。Excel 的外購／自製分類也不是零件功能類別。若舊程式保留來源欄，須確認它不與實際供應商清單互相覆寫。
- 八種零件類別從 `KD\IQC\iqc_category_mapping.json` 匯入，每零件一類；分類可在草稿修改。對照檔中 8 個 `user_explicit` 編號是使用者指定，其餘是討論例子整理的**初始分類**；不能宣稱 Excel 自帶此分類。JSON 在 `KD\IQC` 或 `KD\IQC\iqc_ui_reference` 時，以實際現存者為準，避免硬寫死單一路徑。
- Excel 原資料欄與規則的解讀可能不完全等同新的批次／時間表單；保留原始越文與數值，在匯入異常清單標出無法可靠解析者，不可把缺值自動補成 `AQL 0.25` 或任意數字。
- 截圖只證明畫面顯示 187／187，不等於重開後、另一身分登入後也已持久化。Codex 須核對 local 實際資料庫、來源照片關聯及草稿／送審操作後再回報；不要清空現有 187 筆重新匯入。兩個原檔無圖的零件應可保存並顯示無圖。
- 中文／越文切換只作用於標題、欄位標籤、固定選項；零件名稱、供應商、類別名稱、自訂文字與 Excel 內容照越文儲存與顯示。自訂類別不強制產生中文翻譯，必要時中文介面也顯示其越文原名。

## 六、最小驗收

1. 編號／名稱搜尋輸入 `3` 只顯示單一 `3`；退格與越文輸入正常，搜尋和供應商／類別篩選可合併。
2. 列表每筆只有一張縮圖和其下兩個小按鈕；點縮圖看全部照片；供應商、類別管理彈窗在數十筆資料下仍可搜尋、編輯、新增及安全刪除。
3. 進入編輯模式：修改零件第二供應商、調整照片順序、修改第 2 個檢查項目的 2 條規則，儲存草稿後收合／重新選取／重新整理仍完整；刪除兩次確認，最後一條規則不可刪。
4. 登出重新登入仍有 187 個零件、538 個原始錯誤代碼、538 個原始項目；草稿送審、版本確認平台核准／發回在 local 可操作且生效版不被未核准草稿覆蓋。

請修改現有專案並自行驗證；只操作 local。最終報告逐項標出通過／失敗，不要把示意圖當成已經通過測試。
