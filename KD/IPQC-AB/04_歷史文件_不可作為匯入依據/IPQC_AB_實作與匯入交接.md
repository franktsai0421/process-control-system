# IPQC-AB 線實作與匯入交接

## 目的與畫面

將品質系統的 `IPQC` 入口改名 `IPQC-AB線`。沿用目前 FQC 頁面的版型：淺色背景／白色卡片、深綠側欄、深綠的選中頁籤與資料列、橘紅色送審主按鈕；詳見同目錄兩張 `FQC_版面參考_*.png`。此前綠色草圖已按此方向調色，但正式實作應以現有 FQC 的設計變數與元件為準，不另建一套全域 CSS。

頁面位於**品質系統的資料後台 → IPQC-AB線**；依 2026-09-26 決定，IPQC-AB 頁面**不提供 Excel 匯入、匯出、下載空白範本或匯出目前版本按鈕**。下文的「匯入」僅指建置階段使用 v2 來源檔進行離線核對、預覽及隔離測試資料匯入，不是員工日常操作的網頁功能。

草稿版本卡按 `參考_草稿版本按鈕配置.png` 排列：左側版本狀態／生效資訊，右側依序「查看版本／草稿」下拉、「儲存草稿」、「送出審核」；首次測試送審作為左側次要入口保留，不佔右側按鈕列。生效版唯讀，草稿版可改。頁面由上到下為：版本及草稿卡 → **可收合的操作歷程** → **獨立可收合的報錯／待補及逐筆「前往設定」** → 產線／產品群組／製程與搜尋 → 錯誤代碼列表（查看完整內容／增改刪）→ 所選代碼的檢查項目列表（查看／增改刪）→ 勾選矩陣 → 僅顯示未涵蓋產品。**沒有獨立審核預覽或底部版本紀錄區，也沒有未涵蓋產品的「分配檢查項目」按鈕。**矩陣的直列為檢查項目，橫欄為產品；同一編號同一份標準。勾選即包含、取消勾選即不包含；原始 Excel NO 顯示未勾選，來源及異動歷程仍保留。新增、修改、刪除走彈出視窗，刪除要顯示影響與原因。瀏覽生效資料唯讀，草稿才允許編輯。草圖中的本機儲存僅為 UI 驗證；正式系統草稿需以既有後端持久化，重新登入仍可讀取。

錯誤代碼彈窗：所屬 A／B 線、已匹配產品群組、既有製程、唯讀自動編號、越文名稱、變更原因。項目彈窗：唯讀所屬錯誤代碼與自動接續編號、標準 G、可新增與刪除的多張「標準照片」、檢查方式敘述 J、另外一組選填的「檢查方式圖片」K、目視／從檢具清單選一個設備 L、檢驗方法 M、共用頻率規則 N、項目啟用 O、備註與變更理由。檢查項目「查看」必須顯示標準照片與檢查方式圖片的縮圖，點開可看完整圖片；編輯草稿新增／刪除照片後需連同項目版本可靠儲存，重新登入可查看。正式網站使用既有圖片儲存服務與資料庫關聯、版控和權限，不能照搬草圖瀏覽器本機儲存或把檔案存成資料庫中的 base64 字串；來源 Excel 沒有的標準照片保持空白，照片皆選填，不阻擋送審。欄位採標籤在上、輸入框在下；工具設備連到既有類別→子類別→規格群組的設備清單。產品不同標準，要在同一錯誤代碼下新建項目編碼，不能對同一項目做產品專屬允收值覆蓋。

刪除規則：草稿內可直接刪除錯誤代碼或檢查項目，操作後立即不再出現在**該草稿**列表；刪除錯誤代碼時，彈窗須提示其下項目與產品關聯的影響。若記錄已在生效版中，草稿的刪除仍須隨該產線＋類別正式送審，經確認後才從現行生效版移除。歷史版本與已產生的檢查紀錄保留當時原代碼和標準，可查詢追溯；測試審核確認不套用刪除。不得重用已刪除編號。

## 來源欄位及資料關係

| 來源 | 目標／處理 |
| --- | --- |
| A、B、C | A/B 產線、產品群組、製程：分別對應既有 AB 產線類別及線別／工段主資料的 ID；C 是不含 A-/B- 前綴的製程展示名。未匹配列表人工確認，不自動新增主資料。 |
| D、E | 錯誤代碼和越文名稱，例如 `A-BORUAXE1021-ASSY-L1` → `Kiểm tra zoong`。錯誤代碼歸屬線＋群組＋製程。 |
| F、G | 檢查編號與 IPQC 項目標準，例如 `A-BORUAXE1021-ASSY-L1-01`。G 若空白則待補；保留空白，不自動複製鄰近標準。 |
| H、I、T | H 多行產品編碼／名稱須逐個拆分連回本類別產品 ID；I 若存在保留作來源名稱，顯示以主資料為準；T 備註列出原始 NO 的編碼，關聯狀態要依 T 還原。產品和項目是多對多。 |
| J、K | 檢查方式敘述與圖片；K 可空，J 的來源空白留待人員填寫。圖片不可憑空建立連結。 |
| L、M、N | 目視或一件既有檢查設備、檢驗方法、頻率；不明來源文字保留供核對，不轉成已確認選項。頻率由同一項目下所有勾選產品共用；不提供產品頻率例外欄位或按鈕。 |

頻率表單沿用 IQC 已定規則：每個檢查項目至少保留一條規則；「按批次／依樣品」可選 AQL、固定件數、批次數量或自訂，填對應數值，自訂另填越文名稱；「按時間」可選週、月、季、半年、年或自訂，**不填數量**，自訂只填越文名稱。規則可新增多條、刪除非最後一條；來源不明時保留待補提醒，草稿可先保存。頻率只在檢查項目設定，勾選此項目的產品共用，不提供個別產品頻率例外；若產品確須不同頻率，另建同一錯誤代碼下的項目編號。
| O、P、Q、R、S | 項目啟用、來源版本／變更時間／原因／建立者；原值完整保留，新版由審核流程另記異動。O=YES 不會把產品關聯 NO 改成 YES。 |

編碼以線別開頭。第 83 列已修正為 `A-BORUAXE1021-PACKING-L2`，其 F83／F89／F90／F91 為 `...-PACKING-L2-01`～`04`；匯入時防止將此四筆落在 FINAL。每個錯誤代碼可有多檢查項目；每項目可有多產品；矩陣只有勾選 YES（包含）及未勾選 NO（不包含）兩態。原始 NO 與未曾分配均顯示未勾選，來源 NO 仍在匯入紀錄保留；不提供第三種移除關聯操作。

## 匯入順序與資料保護

1. 唯讀掃描當前 repo、FQC、AB 主資料、設備清單、品質版本平台及資料庫遷移規範。記錄 commit、現有版別與目標環境；不改已合併的 migration。
2. 解析 Excel 的合併儲存格，以最近的上方父層儲存格還原 A/B/C/D/E 等值；不得把相鄰產品行當成新錯誤代碼。僅 F 欄真正有編號的行作項目。若 F 相同的延伸行存在，須合併回同一項目，產品不能遺失；原統計表保留原樣。
3. 產出**逐筆預覽／差異報告**：來源筆數與去重計數、缺 G/J/L/M/N、含 NO 的產品關聯、群組／製程／產品／設備對應、重複或不合編碼、原始來源列號。A 線 35 與 B 線 40 個有項目的群組先比對主資料；B 線 6 個無項目群組只列來源異常說明，不建立空項目。對未匹配的群組／產品，列出候選但由人員指定既有主資料 ID；來源名稱衝突時不猜。
4. 建立可重跑、不重複的測試或草稿匯入：按來源編號及關聯唯一鍵更新同一批次，保留來源欄位與匯入批次雜湊，避免重跑累加；使用交易或可回復的版本寫入，不覆蓋生效主資料。真實產品與工段來源先與主資料匹配。匯入前後筆數及 NO 狀態需核對。
5. 在測試環境完成矩陣、彈窗、草稿留存、審核與發回整個流程，再比較原有 FQC 與其他品質頁是否受影響。正式環境寫入與發布應先呈現本次匹配表、差異報告、測試結果及目標版本供檢視。

## 缺漏、覆蓋與送審

- 橘色是**待補／待確認**，不表示需要在 Excel 當場改完才能匯入。G 空 731、J 空 1,112、L 來源不明 737 的已分配 YES 項目阻擋正式送審；K 圖片可空；M 765、N 760 為提醒，不阻擋。若 L 原文同時描述目視及設備，列待人員二選一。原始 NO 約 283 筆要保留 NO，只有 NO 的錯誤代碼不啟動覆蓋檢查。
- 以每一個錯誤代碼下**所有**檢查項目的 YES 關聯合計產品覆蓋。錯誤代碼只要已有至少一個 YES，就檢查本線本群組、啟用且經過該製程的每一個產品是否至少有一個有效項目。主資料明確說明產品不經此製程才能排除；資料不明則列待確認，不擅自排除。未涵蓋列表可帶入產品與錯誤代碼回矩陣。
- 送審單位是「產線＋產品群組」。未分配任何 YES 的待補項目不阻擋其他已完成內容送審，但本身不生效；已有 YES 的缺 G/J/工具或已啟動覆蓋但漏產品，擋該類別的正式送審並提供「前往設定」。缺圖片、檢驗方法或頻率僅提醒。
- IPQC-AB 線的**測試單與正式審核單都進入版本確認平台頂部的「品質系統資料庫」分頁**，歸在 `IPQC-AB線` 下；不進入「主資料送審」或「製程版本確認」。審核清單標出測試／正式、產線、群組、版本、提交者、時間及缺漏數。
- 首次**測試送審**仍生成缺漏清單，但缺漏不阻擋測試單到達「品質系統資料庫」。審核人可確認／發回，結果、審核人與時間回寫 IPQC-AB；**測試單即使沒有任何缺漏，確認後也只記錄測試結果，永遠不更新生效資料**。測試確認不可共用正式審核的生效動作。
- 正式「送出審核」仍需通過阻擋規則，正式單在「品質系統資料庫／IPQC-AB線」確認後才更新該線＋類別的生效版；發回保留草稿。須留下修改者、審核者、時間與理由。

## 驗收時要核對

- v2 的完整 1,112 個檢查編號和 376 個錯誤代碼有可追溯來源列及正確父層，沒有因合併儲存格漏列；B 線 6 個只有群組名稱的不會創建項目。
- 原 Excel 283 筆 NO 產品關聯可逐項核對；重跑匯入筆數、版本、關聯狀態不增加或變異；未知產品、群組、工段、設備有清單，未解決的對應不被默默匯入。
- 結構按「錯誤代碼 → 檢查項目列表 → 項目列 × 產品欄矩陣」，編輯彈窗與 FQC 品質站風格一致；手機矩陣可橫向捲動。
- 草稿重新登入／重開瀏覽器仍在；已啟動覆蓋時未分配產品擋正式送審；未分配項目與頻率待補只提醒；測試單與正式單都顯示於版本平台的**品質系統資料庫**，測試單即使無缺漏也僅能確認／發回、不改生效版；正式確認後只有所選類別換新版本。
- 在草稿刪除項目或代碼後，草稿列表立即更新；正式確認前舊生效版仍可使用；正式確認後現行版移除該內容，但歷史版與既有檢查紀錄仍可查原代碼；測試確認不套用刪除。
