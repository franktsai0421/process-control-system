# IPQC-AB 線資料與介面框架（討論稿）

基礎檔案：`IPQC_CHUAN_AB_編碼調整_v2.xlsx`。本稿只定義討論方向，尚未修改網站、匯入資料庫或發布。

## 1. 資料來源與層級

| 層級 | Excel 來源 | 網站資料來源與關係 |
| --- | --- | --- |
| 產線 | A 欄 `LINE A`／`LINE B` | 連至中控系統既有 AB 產線主資料。只顯示 A、B。 |
| 產品群組 | B 欄，如 `BORUAXE1021` | 連至所屬產線的「AB 產線類別」主資料；以線別＋類別 ID 作關聯。 |
| 製程 | C 欄，如 `ASSY` | 連至「線別與工段管理」的 A/B 製程；畫面可顯示 `ASSY`，對應主資料代碼 `A-ASSY`。 |
| IPQC 錯誤代碼 | D 欄，如 `A-BORUAXE1021-ASSY-L1` | 隸屬一個產線、產品群組、製程；E 欄 `Kiểm tra zoong` 是名稱。 |
| 檢查項目 | F 欄，如 `A-BORUAXE1021-ASSY-L1-01` | 隸屬一個錯誤代碼；G 欄是該項目的標準，不是錯誤代碼名稱。 |
| 適用產品 | H 欄中的多行「編碼＋名稱」 | 每行解析為產品編碼，核對後連至 AB 產品主資料；以多對多關聯保存，名稱由主資料顯示。 |

新增或移除主資料類別／製程時，頁面的選項和分類同步反映主資料；既有 IPQC 記錄保留原關聯與版本，不因主資料移除而被連帶刪除。停用或找不到的關聯要顯示為待處理。

## 2. 檢查項目的基本資料

| Excel 欄位 | 頁面欄位 | 編輯方式 |
| --- | --- | --- |
| F | 檢查編號 | 依錯誤代碼自動接續、唯讀、不重用。 |
| G | IPQC 項目標準 | 同一檢查編號共用一份標準。若產品需要不同允收值，在相同錯誤代碼下新增另一檢查項目與新編號，分別勾選適用產品；不設定產品專用標準覆蓋。 |
| H | 適用產品 | 多選本線本類別的產品；顯示產品編碼與名稱。 |
| 新增欄位（Excel 無） | IPQC 項目標準照片 | 每個檢查項目可上傳多張標準照片，保存後在項目「查看」中顯示縮圖，點開看大圖。與 K 欄檢查方式圖片分開存取；照片選填，不阻擋送審。 |
| J、K | 檢查方式敘述、圖片 | J 為必填的檢查方式文字；空白的已分配項目阻擋正式送審，顯示「前往設定」。K 可放多張圖片；沒有圖片不擋送審。來源空白不自動杜撰。 |
| L、M、N | 檢驗工具／設備、檢驗方法、頻率 | L 必須在「目視」與「檢查設備」中二選一；選設備時按類別、子類別、規格群組挑選現有檢具。L 為空白或 `CHƯA CÓ DỮ LIỆU NGUỒN` 等未知來源的已分配項目阻擋正式送審。Excel 若同時列目視與設備或多種工具，列待人工選定單一方式，不自動選擇。保留 M、N 的 Excel 原文；頻率沿用 IQC 多條規則方式，所有勾選該項目的產品共用；不提供產品個別頻率例外。班初／班中／班末、換碼與客戶條件需能表達。頻率未知、空白、單寫 `1` 等列「待補提醒」，不阻擋送審。 |
| O | 項目是否啟用 | 依 v2 來源保留 `YES`；若 G 欄標準缺漏，項目狀態先列「待補」。沒有任何產品 `YES` 關聯的待補項目不擋送審，但不生效；有產品 `YES` 關聯的缺標準項目阻擋送審。項目啟用與產品關聯狀態分開。 |
| P、Q、R、S | 版本、變更時間、原因、建立者 | 後續修改由版本流程記錄使用者和時間，保留匯入時來源值。 |
| T | 備註 | 保留 Excel 備註，並依「Trạng thái SKU nguồn NO:」後面的產品編碼還原各產品關聯的原始 `NO`。 |

產品關聯另外記錄 `YES`／`NO`：v2 備註明確列為原始 `NO` 的產品保留 `NO`；其餘產品依來源狀態帶入，不能因項目 O 欄是 `YES` 而把產品的 `NO` 改成 `YES`。若缺乏可判定的來源狀態，列入匯入差異報告人工核對。

3. 主列表：依產線 → 產品群組 → 製程列出錯誤代碼，顯示代碼、越文名稱、檢查項目數、已覆蓋產品數及未完成數。點開錯誤代碼，先列出其各個 `-01`、`-02` 檢查項目與標準，再往下顯示矩陣。錯誤代碼與項目列表各自提供新增、修改、刪除操作。
   新增、修改錯誤代碼及檢查項目都以彈出視窗處理；刪除也先彈出確認及原因。錯誤代碼視窗顯示產線、群組、製程與自動產生的代碼，填寫越文名稱、變更原因；項目視窗顯示所屬錯誤代碼與自動檢查編號，填寫標準、可保存並查看的標準照片、檢查方式敘述與另外一組選填的檢查方式圖片，從目視／設備擇一，設定檢驗方法、共用頻率規則、啟用狀態與變更原因。適用產品可於下方矩陣勾選。草稿中的代碼或項目可直接刪除並立即從草稿列表移除；如該內容已存在生效版，刪除屬於此類別的新版本變更，只有正式審核確認後才從現行生效版移除。舊版本及既有檢查紀錄仍保留原代碼、標準和來源，不因刪除而失去追溯。
4. 項目詳情：標準、適用產品清單、檢查方式敘述與圖片、工具／設備、檢驗方法、頻率、啟用、備註、版本資訊。修改時填變更理由。
5. 產品覆蓋視圖：先選產線與群組，可再篩製程、錯誤代碼；以檢查項目為列、產品為欄，沿用 FQC 勾選矩陣。勾選 `YES` 表示包含，未勾選 `NO` 表示不包含（包含 Excel 來源 NO 與未曾分配的產品）；標準待補在項目列提示。草稿模式下直接勾選或取消勾選即可切換兩態；來源狀態及變更保留於匯入／操作歷程供追溯。瀏覽唯讀，草稿模式才可修改。
6. 矩陣下方**只顯示**「目前錯誤代碼尚未分配有效檢查項目的產品」，不提供分配按鈕。覆蓋檢查以每一個錯誤代碼為單位，合計其底下**所有**檢查項目的產品關聯：只要其中有至少一個啟用的產品關聯為 `YES`，該錯誤代碼即開始檢查本線、本群組所有啟用且**經過該製程**的產品，要求每個符合條件的產品至少勾選該錯誤代碼下**其中一個**有效檢查項目；不要求每個檢查項目都涵蓋所有產品。同群組產品通常共用製程路線；只有主資料明確顯示某產品不經過該製程時，才將其排除覆蓋計算並標示原因，產品路線資料不明時不自動排除。錯誤代碼及其項目若完全沒有產品 `YES` 關聯（含只有原始 `NO` 的情況），不啟動產品覆蓋檢查。原始 `NO`、標準待補、停用項目與無關聯不算有效涵蓋；若同一錯誤代碼已有啟用分配，這些產品仍列入缺漏。送審時依各已開始分配的錯誤代碼列出遺漏產品；修正導覽統一放在頂部「報錯／待補」的逐筆「前往設定」。
7. 點頂部「報錯／待補」中的「前往設定」帶入產線、群組及錯誤代碼，前往對應檢查項目或矩陣；可勾選標準相同的現有項目，或在**同一錯誤代碼**下新增檢查項目及自動接續編號。產品標準不同必須新增項目，不得在現有項目覆寫標準。
8. 共用版本流程：開始修改 → 儲存草稿／送出審核 → 版本確認平台的品質系統資料 → 確認生效或發回；記錄修改者、審核者及時間。**送審單位是「產線＋產品群組」（類別）**，例如 A 線 BORUAXE1021 完成後可單獨送審，不等待 A 線 BOSEN 或 B 線其他類別。按該類別的「送出審核」時，只檢查此類別底下已分配產品的錯誤代碼：任一已分配產品 `YES` 的項目缺標準、缺 J 欄檢查方式敘述、缺 L 欄工具選擇，或任一已啟動覆蓋檢查的錯誤代碼漏掉該類別適用產品，就阻擋**此類別**送審。問題清單依製程／錯誤代碼／檢查項目顯示，提供「前往設定」帶到正確項目或矩陣；修好後重新檢查再送。其他類別的待補、此類別沒有圖片或頻率待補、尚無產品 `YES` 關聯的待補項目只提醒，不阻擋此類別送審。版本確認平台的審核單標明產線與類別，確認後**只更新該類別生效資料與版本**；其他類別的草稿與生效資料均保留，發回也只作用於此類別。

### 首次測試送審（驗證版本平台連結）

- 首次測試針對所選的「產線＋類別」提供明確標示的「測試送審」操作：先儲存該類別當前草稿，照常產出標準、檢查方式、工具及產品覆蓋等問題清單與數量，但僅此次測試不阻擋提交測試審核單。正式「送出審核」依第 8 點持續阻擋，不能共用繞過開關。
- 測試與正式審核單均進入版本確認平台頂部的「品質系統資料庫」分頁，歸於 `IPQC-AB線`，不送到「主資料送審」或「製程版本確認」分頁。顯示測試／正式標記、產線與類別、送審者、時間、版本或草稿識別及缺漏摘要，讓使用者驗證平台能看到資料、執行確認或發回、回傳審核人與時間。
- **測試單無論內容是否已填完整**，在平台按確認或發回，都只記錄測試流程結果，**絕不使任何草稿生效**，也不覆蓋現行已生效資料；返回 IPQC-AB 時仍可繼續編輯原草稿。測試單確認的操作不得呼叫正式生效程序。
- 測試完成後正式送審規則仍生效。只有按「正式送出審核」，通過標準、檢查方式、工具與產品覆蓋檢查，並在「品質系統資料庫」獲正式確認後，才更新該產線＋類別的生效版。驗收：測試單可在品質系統資料庫確認／發回並回顯結果，但即使資料完整也不改生效版；正式送審缺漏時仍被阻擋。

主資料新增的產品立即出現在所屬產線、群組的矩陣；對已啟動覆蓋檢查的錯誤代碼，若該產品尚未分配有效項目，顯示於「未涵蓋」。新增產品不追溯撤銷已生效版本；下一次**所屬類別**送審前，須完成新產品分配。產品製程路線缺漏列「製程路線待確認」，提供前往中控產品主資料的入口；路線不明時不自行排除產品。

1. G 欄沒有標準的 731 個檢查項目先列「待補」：無產品 `YES` 關聯的不擋所屬類別其他內容送審，且自身不生效；有產品 `YES` 關聯的須補標準才可送審該類別。
2. 未匹配產品群組逐一核對並對應既有 AB 主資料類別；不自動建立類別。
3. 產品關聯依 Excel 原始狀態匯入。備註明列原始 `NO` 的 283 筆關聯保留 `NO`；其所屬項目的 O 欄 `YES` 仍獨立保存。
4. 第 83 列製程與編碼不一致已改為 `PACKING`，包含 4 個子檢查編號；仍待核對匯入時找不到或已停用的主資料關聯。
5. 同一項目共用標準，產品標準不同須另建項目編號；頻率由同一檢查項目下勾選的產品共用，不提供個別產品頻率例外。頻率缺漏列「待補提醒」但不擋送審。每個錯誤代碼只要有一個產品 `YES` 關聯，就須由其所有檢查項目合計涵蓋該線、該群組啟用且經過該製程的產品；只有 `NO` 或完全未分配的不啟動覆蓋檢查。明確不經該製程的少數產品不算遺漏；矩陣下方只列出其餘未涵蓋產品，送審前阻擋並由頂部「報錯／待補」提供設定入口。
6. 矩陣勾選 `YES`、取消勾選 `NO`，無第三種移除動作；主資料新增產品顯示未涵蓋，不追溯取消既有生效版，下一次送審須補分配。匯入異常逐筆顯示並處理。
7. IPQC-AB 以「產線＋產品群組」為單位分開送審與生效：只檢查本次送審類別內已分配產品 `YES` 的項目是否缺標準、缺檢查方式文字 J、缺目視／設備選擇 L，以及已啟動錯誤代碼的產品覆蓋；有問題就阻擋此類別正式送審並連到設定位置。缺圖片 K、頻率待補只提醒；其他類別的問題不擋此類別。
