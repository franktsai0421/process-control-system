# 01 規格與資料結構

## 目標與資料所有權

頁面位於 **品質系統 → 資料後台 → IPQC-AB線**，使用目前品質資料後台的深綠／淺色／白色卡片。來源主資料為中控「AB 產線與類別」及「線別與工段管理」；IPQC 僅保存檢查規則、編碼、產品勾選與版本，不能建立或覆寫主資料。

資料階層：線別 A/B → 中控線別下的產品群組 → 產品工段流程中的工段 → IPQC 錯誤代碼 → 檢查項目 → 適用產品關聯。例：`A-BORUAXE1021-ASSY-L1`（錯誤代碼）／`A-BORUAXE1021-ASSY-L1-01`（檢查編號）。正式新增編號由後端在選定線別、群組、工段和父代碼後自動遞增；既用編號不重用，欄位唯讀。線別／群組／工段若不在中控主資料中則不得直接建 IPQC 記錄。

產品只展示該 AB 線、該群組既存且工段路線經過所選工段者。主資料新增／停用產品時重新計算候選清單；IPQC 勾選不修改主資料。Excel 中不符合中控主資料的產品或群組不匯入，出具含來源列號的差異報告；群組名稱不同先核准映射及代碼變更，不能只按相似字串套用；產品名稱以中控主資料顯示，Excel 名稱保留來源稽核欄。

## 三種不同的狀態

| 狀態 | 含義 | 結果 |
| --- | --- | --- |
| 檢查項目啟用 YES/NO | 該項目是否用於現行檢查 | 與檢查方式、設備和產品勾選互不代替；停用保留草稿關聯和歷史。 |
| 矩陣勾選 YES/NO | 該產品是否包含此項目 | 僅二態；沒有「移除關聯」、沒有產品標準／頻率例外。 |
| 草稿／正式已確認／測試單 | 版本流程狀態 | 草稿及測試單不使資料生效；正式單核准後才替換該線＋群組生效版。 |

實際可使用項目須同時具備：中控產品仍符合線別、群組、工段；產品在項目矩陣勾選 YES；項目啟用 YES；所屬版本正式核准。目視與檢查設備二選一；**首次匯入全部預設目視**，保留來源 L 欄但不建立設備關聯。之後人工選設備時須指向現有且可選的檢具。設備圖示只在檢查項目列表中顯示，不加 IPQC 頁內「檢具與測試設備・標準引用」區塊；檢具頁原有反向引用仍須按 FQC／IQC 模式連動，且每個項目逐筆顯示。檢查方式敘述與項目啟用為各自獨立欄位。

同一檢查編號只存一份項目標準、一組可多條的檢查頻率與多張照片，套用到所有勾選產品。若產品允收標準不同，建立不同檢查編號，不提供產品個別頻率例外。標準照片及檢查方式圖片分開保存，均可多張；列表縮圖點開可切換全相簿。照片選填，草稿與核准版本都必須可持久保存，不能只存瀏覽器物件 URL。

頻率遵循現行 IQC 的按批次／依樣品及按時間規則，可多條：按批次 AQL、固定件數、批次數量或自訂；按時間週、月、季、半年、年或自訂。項目共用，缺漏／`1` 無法確認時標橘色待補，現階段只提醒不擋送審。不要在 UI 寫「與 FQC 共用」。

## 覆蓋、待補與審核

矩陣直列檢查項目，橫列中控候選產品。對同一錯誤代碼，已啟用項目的產品聯集決定覆蓋；全無有效 YES 也列未涵蓋待補。涵蓋不足不阻擋送審或核准，提醒可導向對應錯誤代碼矩陣修正。停用項目原有勾選可保留供日後修改，但本次不算有效覆蓋。

正式送審以**線別＋群組**為範圍，各群組可分開送。[最新 IPQC 送審政策](../../docs/specs/current/IPQC_POLICY.md)取代舊敘述／涵蓋限制；檢查標準及必要檢具的既有要求保留，問題區指向具體項目。變更理由僅有實際資料差異時必填；草稿重開後保留，核准前後資料及歷史可追溯。

舊「測試送審」入口已移除；既有測試案件及歷史保留且不能成為生效版。正式案件送至**版本確認平台 → 品質系統資料庫 → IPQC-AB線**。正式單通過檢查且經該分頁核准後才生效；同類別待審與併發修改依現有版本平台的衝突處理。草稿新增／修改／刪除及已核准資料刪除須保留歷史；已有下層或歷史引用的刪除權限依現行品質系統限制檢查。

## 頁面順序

版本／草稿卡 → 操作歷程與報錯／待補兩個獨立收合列 → 線別／群組／工段 → 錯誤代碼列表（查看、增改刪）→ 檢查項目列表（啟用、方式／設備、頻率、縮圖、查看增改刪）→ 產品矩陣 → 未涵蓋名單。新增與修改開彈窗。網頁不放 Excel 匯入／匯出、底部審核預覽或底部版本紀錄。
