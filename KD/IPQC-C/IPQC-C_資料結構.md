# IPQC-C 資料結構與主資料關聯

## 關聯與責任

| 實體 | 建議識別與欄位 | 權威來源／編輯權 |
| --- | --- | --- |
| C 線產品 | 產品代碼、目前名稱、類別、有效線別 | 現有「C 產線與類別」主檔；IPQC-C 唯讀。 |
| 製程／路線 | 工段穩定 ID、縮寫、名稱、產品的有序路線、既有停用狀態 | 現有「線別與工段管理」與產品路線；IPQC-C 唯讀。 |
| IPQC-C 錯誤代碼 | `C-產品-製程-L序號`、所屬產品及工段、名稱、備註 | IPQC-C 草稿與版本管理；同產品＋工段可有多個代碼。 |
| IPQC-C 檢查項目 | `錯誤代碼-項目尾碼`、所屬錯誤代碼、標準、敘述、工具、方法、頻率、標準啟用、CPK 啟用、備註 | IPQC-C 草稿與版本管理；一個錯誤代碼可有多個項目。 |
| 圖片／歷史 | 項目圖片引用與順序、版本、操作者、審核、已發號紀錄、檢查紀錄引用 | 網站既有儲存及共用版本流程；首次來源 Excel 不帶圖片資產。 |

關聯順序為「**C 線產品 → 產品當前製程路線 → 錯誤代碼 → 檢查項目**」。縮寫如 `C-PREP` 與工段主檔的穩定識別相連；上游名稱變更只更新顯示，不能重新建立一份 IPQC-C 工段主檔。

## 編號與版本

最新 862 筆來源在**首次建置前**依使用者修正的工段同步過 E/G；這是來源整理。建置時先查網站是否已有相同編號或引用舊號的紀錄；發現衝突須顯示映射及影響，不能默默視為刪除舊項再新增。

網站正式發號由系統執行，表單中唯讀；於產品＋工段／代碼範圍接續，避免並行草稿撞號。已發號無論取消草稿、刪除或停用，都不回收。刪除只使項目退出目前生效清單，歷史版本與檢查紀錄仍能追溯。多人修改依[共享草稿](../../docs/specs/current/SHARED_DRAFT.md)及revision／dependency guards，不重建個人草稿或三值衝突方案。

CPK 啟用與標準啟用分開儲存；執行清單條件是 `standardEnabled && cpkEnabled`。現有 CPK 計算與量測表單不屬於本次標準管理實作。

若產品日後不再屬 C 線或工段移出路線，保留既有標準及歷史，標示已不在現行路線，停止為該歸屬新增；不可因主檔變動自動物理刪除標準。

## 語言儲存

以越文 `vi-VN` 作預設介面，中文 `zh-TW` 只切換介面字串。來源業務文字與編號儲存一份原值；既有產品主檔名稱照主檔顯示，不因 UI 語言變更而覆寫。來源狀態碼轉為布林值，介面以對應語言顯示；若未來要在中文介面顯示翻譯後的檢查標準，需另設人工審核的中文欄位與翻譯版本，不能修改原越文標準。

Excel 只用於開發流程首次建資料，不建立日常 Excel 上傳或匯出 API／按鈕。
